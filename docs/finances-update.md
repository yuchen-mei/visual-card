# Finances 更新流程

当前运行方式使用已连接的 Finances、GitHub 工具和用户 Mac 上的固定脚本。密码从仓库外已有的私有文件读取；本流程不使用 Keychain，不创建新定时任务。Mac 和工具运行环境必须在线，不能视为脱离 Mac 的独立云端程序。真实试跑、发布和任务启用状态应分别核实，本文不代表这些动作已经完成。

## 密码与本机入口

运行时配置 `passwordFile` 为已有密码文件的绝对路径。文件必须在仓库外，属于当前用户，权限精确为 `0600`；父目录必须属于当前用户且权限为 `0700`。程序拒绝符号链接、多重硬链接、读取期间变化和不合法的输入。配置中只保存路径，不保存密码值。

`finances_tool_runtime.cjs` 使用该配置调用以下入口；路径均为占位符：

```sh
node scripts/finances_daily.cjs --serve-file \
  --expected-head '<MAIN_COMMIT_SHA>' \
  --baseline '/private/visual-card/baseline.enc.json' \
  --output-dir '/private/visual-card/candidates' \
  --password-file '/private/visual-card/website-password'
```

此入口等待运行时通过 stdin 提交一次加密数据包，不会自行查询 Finances 或发布 Git。运行时直接处理会话头和原始工具响应，不显示或保存它们；密码、明文投资数据不得进入 Git、命令参数、普通环境变量、日志或报告。脚本只输出受限状态和已验证的加密候选回执。已有的匿名密码描述符入口继续兼容，但日常文件模式不需要原生 helper。

## 真实数据读取与交易合并

1. 从 GitHub main 读取最新 head 和 `data.enc.json`，绑定密文原始字节的 SHA256。独立批准的账户哈希集合必须与真实账户范围一致。
2. 查询全部目标账户余额及券商完整持仓分页，核对现金、证券市值、账户总额和独立总资产。银行与券商现金统一展示为“现金”，不显示来源。
3. 对每个投资账户查询未加日期或其他过滤的 `investment_transactions`，按 `date` 升序逐页读取；运行时使用每页 20 条。来源适配器检查请求、结果索引、账户、所有 cursor 链及重复交易 ID。缺页、游离页、查询变动或缺失账户都停止运行。
4. 仅规范化 `buy/buy` 与 `sell/sell`。供应商买入数量和金额必须为正，卖出必须为负；规范化后股数为绝对值，金额美分保留原符号。记录中的 ticker 可用于已卖出证券，不依赖当前持仓。日期明确采用供应商结算日 `provider-settlement-date`，不能拿 `transaction_datetime` 推断成交日或补齐缺失日期。
5. 来源中的明确现金、利息、股息、转账和费用记录不在本步骤生成收入或交易；已知 `fee / miscellaneous fee` 可跳过。取消、公司行动、带非零数量及非现金证券依据的转入转出、未知类别、必要字段缺失或金额方向异常会停止，不静默遗漏。

`allPagesFetched: true` 仅表示观察到每条查询链正常结束。`sourceAsOf` 和 `queriedFrom` 保留 `null`，`historyFromInception` 为 `false`；账户同步或抓取时间不能变成来源更新时间，也不能证明取得成立以来完整历史。

`finances_trades.cjs` 保留全部 legacy 订单及原 `historySnapshot`。首次合并要求原订单的最晚日期与历史快照日期一致，并将其固定为 `baselineCutoff`；以后不会随新订单向前移动。只追加严格晚于该边界的真实买卖记录。稳定 ID 由账户 ID 和供应商交易 ID 的组合散列得到，原始 ID 不进入输出订单。

已经同步的 ID 必须仍存在，且日期、ticker、方向、股数、价格、金额及费用均未变化；缺失或变化时拒绝本次更新，避免自动改写历史。相同数据重复执行不会重复追加订单。边界以前的缺口不会被推测补齐。保留旧历史并追加当前交易，不等于完成完整历史重建或年度收益重算。

首次接入时，新记录若与任意旧订单的 ticker、方向、股数及价格完全相同，会拒绝并要求核实，防止旧成交日与新结算日不同导致重复。

## 校验与发布

日常更新保留收入、用户确认本金及历史上下文；存在已确认收益公式时，用当前现金、证券市值和成本重新计算收益。内部转账不算收益，历史现金利息不重复计入，未知入账日期保持未知。用户确认本金或累计利息的更正不能由日常流水自动触发。

当仍有未确认到账的购买力补充值时，只有新增稳定 ID 的零手续费买卖能同时解释全部现金及每个证券股数的变化，才自动更新；首次接入或没有新交易时继续要求现金、股数和成本未变。额外入金、费用或其他无法解释的变化会保留旧数据并报告，不能自行推断补充值已经到账。

固定校验器核对账户余额、持仓和网页计算，并验证 Node 与网页 WebCrypto 均能解密候选。密文保持现有 envelope 和 PBKDF2-SHA256 / AES-256-GCM 兼容性。业务数据无变化时不重新加密、不 commit、不 push；仅抓取时间变化不能制造更新。

日常发布只允许变化后的 `data.enc.json`。发布前 main 必须仍是候选绑定的 head；以预期 head 更新 main 后再读回确认。源码发布使用另外审阅的文件清单，不能夹带密码文件、私有配置或明文财务数据。失败或结果不确定时保留旧文件和恢复状态，不盲目重试写入。

既有外部编排可按批准的洛杉矶时间调用此流程；脚本本身不启用任务、不唤醒 Mac。电脑离线时无法完成本地解密、校验和加密，恢复在线后由既有编排决定补跑。故障通知只报告阶段和安全错误码。

## 直接验证

以下测试使用合成数据，不读取真实账户或密码：

```sh
node --test scripts/test_finances_source.cjs scripts/test_finances_trade_source.cjs
node --test scripts/test_finances_trades.cjs scripts/test_finances_password_file.cjs
```

测试通过只证明相应程序契约；正式运行仍需真实 Finances 分页、既有私有密码文件、完整校验和 GitHub 发布回执。
